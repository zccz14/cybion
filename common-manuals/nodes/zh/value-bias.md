# 价值偏置

模型在训练时被刻意去偏见化了，但用户真正要的是**他自己的偏置**：同样两个选项，他和别人选得不一样，而且他认为那是显然的。记忆只让你知道用户是谁；价值偏置才让你在冲突时替他做决定。

这份手册由你替他维护：**捕捉**他在真实取舍上的选择，**记录**成可执行的判据，下次**先用**，用完给他推翻的机会。

## 什么算一条

只记「无法从事实推导出来」的选择。能用规则、文档、成本算出来的，不算偏置。四种形态：

- **两难取舍**：快 vs 对、便宜 vs 稳、省事 vs 可控、隐私 vs 便利——他选了哪个、牺牲了哪个。
- **纠正**：「不，别这样」「这个我不看」——被否决的不是一次操作，而是一类做法。
- **反直觉的容忍**：明知有损仍然接受（「先上，脏数据我认」）。**能容忍的边界**比偏好本身更有信息量。
- **计量单位**：他习惯用钱、时间还是复杂度衡量一件事；预算不够时他会先砍什么。

不算：一次性的临时要求（「这次先用 Python」）、环境事实（「我用 macOS」）、能写进项目文档的技术约定。

## 怎么捕捉（钩子）

三个时机会自然浮现，抓到就别放过：

1. 他做了一次取舍 → 记下「选项 A / 选项 B / 他选了 / 代价」。
2. 他否决了你的方案 → 记**被否决的做法类别**，不是那次操作。
3. 同一个张力第二次出现、且他选择一致 → 把这条写成更一般的判据。

张力出现了但他没表态时：**问一个问题，不是问卷**，而且必须带代价：

- 好：「两条路：A 今天能上线，但脏数据要下周清；B 多两天，上线即干净。你要哪个？」
- 差：「你更看重速度还是质量？」——抽象问题只会得到抽象答案。

一次会话最多问一个；他不回答就按当前最省事的那条走，并在回复里说明你按什么走的。

## 一段怎么写

四段式：`场景 / 张力 / 选择 / 依据`。`依据` 是列表，每条带日期与出处（原话优先）；列表项在 `依据:` 之后空一行再写。

```text
# 价值偏置

> 一条一个场景，四段式：场景 / 张力 / 选择 / 依据。依据是列表，每条带日期与出处；块与块之间空一行。

场景: 故障修复
张力: 彻底修 vs 先恢复服务
选择: 先恢复服务——线上故障优先恢复可用性，根因修复可以排到之后
依据:

- 2026-02-11 · 终极机器磁盘检查

场景: 沟通
张力: 先说结论 vs 先给推导
选择: 结论 + 一句证据——默认答案先行，深度分析放后面
依据:

- 2026-02-02 · 「先说要我干什么」
```

- **场景**：粗粒度类别（故障修复 / 代码风格 / 沟通 / 花钱），不要用项目名，否则复用时匹配不上。
- **张力**：两个都说得通、却只能要一个的东西。
- **选择**：他实际选的那一边，后面直接跟可执行的判断句。写不出判断句，说明还只是偏好——只留依据，别写成规则。
- **依据**：`YYYY-MM-DD` + 出处（Thread 标题、关键词或原话）。只出现过一次的选择，在这条后面注明「仅一次，待二次确认」，不要当成通用规则用。

## 怎么用

- 同类张力再出现时，**先按已记录的块行动**，并点明：「按你之前的选择（先恢复服务），我先…」——给他当场推翻的机会。
- 两块打架 → 按**最近**的那一块，并说明理由。
- 被推翻的块**直接删**，不要留「已过时」。
- 规则频繁冲突，说明粒度抓错了：往上合并一层。

## 止损

- **不写画像**：这不是性格分析。「他喜欢简洁」这种空话一律不写。
- **不升级太快**：只出现过一次的选择留在依据里并标注，等第二次一致再写成判据。
- **不追问**：钩子是为了少问。已有块覆盖的场景不要再确认。
- **不写敏感内容**：薪资、健康、住址、账号、客户名单都不进手册，只写决策形状。
- **一份就够**：顶层、名字建议 `价值偏置`，约 60 行以内；超了按场景合并，不拆子手册。

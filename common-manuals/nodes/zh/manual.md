# Cybion 用户帮助手册

这是 Cybion 自带的操作指南：由源码 `common-manuals/` 编译进二进制，所有用户共享、只读——控制器不在运行时存储或修改它，内容只随版本发布；源码公开，可自行审阅修订历史。

它是产品知识，不是当前用户的数据。需要「如何用 Cybion 自己的功能干活」时按需读，不必一次读完。

优先级：引擎行为与工具契约以每次请求携带的工具描述为准；本手册给使用方式、配方与坑，两者冲突时以工具描述和实际行为为准。

只有这一份，不分设子节点：终极机器、Linkit、加载手册、两份常备用户手册（项目索引、价值偏置）与用户手册格式，都在本页。

## 终极机器

一台终极机器 = 一个 Worker + 一条 bash 检查命令 + 一个运行间隔。按期运行：返回 0 就保持沉默；失败时把修复请求投递到它绑定的修复 Thread（标题「终极机器 · <名称>」）。名字借自贝尔实验室那台唯一功能是把自己关掉的玩笑盒子——平时什么都不做，只在检查失败时现身。

- 调度：创建即跑第一次；此后「上一次落定 + 间隔」开始下一次（慢命令会拉长实际周期）；同一台机器同时最多一次运行。
- 失败：exit ≠ 0（或命令被杀）→ 修复 Thread 收到命令、exit、输出尾部（约 1500 字符）、意图与判据「使该命令返回 0」。
- 离线：运行时刻 Worker 离线或不存在 → 跳过本次、经 Linkit 提醒一次，恢复后自动继续（每个事件只提醒一次）。
- 失联：一次运行 15 分钟仍未落定 → 判定失联、提醒一次，下个间隔重试。
- 丢消息：修复 Thread 正在运行时，新的失败被丢弃而不是排队；所以静默既不代表健康，也不代表机器坏了。
- 即时复查：修复 Thread 那一轮成功结束后立刻再检查一次；该轮自己以 failed 结束则等间隔。
- 暂停：`enabled=false` 停掉定时运行与离线提醒，并取消在途的机器运行和修复 Thread 当前这一轮。
- 删除：彻底移除；修复 Thread 及其历史保留为普通 Thread。删掉修复 Thread 或它绑定的 Worker 会连带删机器；改绑 Worker 视作新的一轮离线提醒。

该开：长期存在、且能自动判定「健康」的检查——资源水位（分区/磁盘/inode/内存交换）、到期类（证书剩余天数、备份窗口、配额）、服务存活（端口可连、systemd active、关键进程）、数据新鲜度（最后一次成功时间戳）、一致性（关键文件存在非空、校验和）。
不该开：一次性或需人判断的事、高频轮询（下限 10 秒）、指望机器自己修（它只发现，修复发生在 Thread 里）、输出可能带密钥/令牌/隐私。

写命令：退出码即语义（0＝健康且沉默，非 0＝失败并把 stderr/stdout 尾部送进 Thread，让失败自己说话）；只读幂等；便宜（单次 300 秒上限，超时被杀同样算失败）；按非交互 shell 写、显式路径，不假设 PATH/locale/时区；输出带期望值与现状，修复者不用二次侦查。

```text
test $(df -Pk / | awk 'NR==2 {print $5}' | tr -d %) -lt 90
openssl x509 -checkend 604800 -noout -in /etc/ssl/certs/server.pem
find /backups -maxdepth 1 -type f -mmin -1440 | grep -q .
```

上手前先干跑：用 bash 在目标 Worker 上跑同一命令，确认健康态返回 0，并人为制造失败看输出是否可读。

管理工具：`cybion_list_ultimate_machines` 看全貌与 id（含 enabled、last_run_at、last_exit）；`cybion_get_ultimate_machine` 看一台的定义与最近结果（last_exit：0＝正常，其他数字＝退出码，被杀无退出码记 -1，null＝尚无落定结果或已失联）；`cybion_set_ultimate_machine` 新建（必填 name / worker_id / command / interval_seconds 10–2592000，可选 intent；只能绑自己拥有的 Worker）或局部修改（只给要改的字段；intent 传空串清空；换 Worker 重启离线提醒；改名同步修复 Thread 标题；`enabled` 只在更新时传）；`cybion_delete_ultimate_machine` 删除——想安静就暂停，只在用户明确要求时删除。

修复流程：get 看定义与最近结果 → 判断是环境问题（用 bash 直接修）还是检查写错（先验证新命令，再 set 更新定义；工具不可用就请用户去页面改）→ 手动跑到 0 → 这一轮成功后机器立刻复查，不必等定时器 → 别为了变绿弱化检查 → 无需回复。失败输出会进 Thread 历史，不要 echo 密钥，只输出布尔判断。机器是用户的资产：只在明确要求或修复需要时创建/修改，批量动作先说计划。

## Linkit（通知与触达）

Linkit（linkit.ntnl.io）是 NTNL 生态的社群与触达产品。每位 Cybion 用户经 Auth Mini 天然拥有 Linkit 身份；连接与凭据只存在控制器侧，不经过你也不经过 Worker。

- 身份与偏好：暗黑模式、语言偏好、共享选择器的候选人都来自 Linkit，由 Web 端与控制器处理，你不需要也无法直接操作。
- 通知：推理成功结束或终局失败时，控制器把结果经「用户 ↔ Cybion Bot」私聊送达；终极机器的离线/失联提醒走同一通道，每个事件只提醒一次。开关默认关闭、由用户控制；被取消/顶替的请求与成功压缩不通知；回执只代表已存入 Linkit，不代表已读。
- 没有 `linkit_*` 工具（设计决定，勿再引入）：不要承诺「我去 Linkit 通知某人」；用户要求主动发送到某个会话时如实说不支持。结论写清即可，通知正文由控制器从 Thread 生成。
- 未来（尚未上线）：Linkit 侧发起的任务可能以 Thread 输入的形式出现，按普通用户输入处理。

## 加载手册

某份手册要跨轮次、跨压缩一直用下去，就用 `load_manual` 挂到 Thread：控制器每次请求附带它的最新副本，内容被改或历史被压缩后自动补发，不必重复读取；不再需要时用 `unload_manual` 释放，副本留到下次压缩自然退休。

## 两份常备用户手册（钩子）

Cybion 期望每位用户长期维护两份用户手册：**项目索引**（项目在哪、是什么）与**价值偏置**（冲突时他会怎么选）。它们不靠用户自觉，靠你在干活的过程中顺手维护：位置出现或变化就补一个索引块，出现真实取舍就记一个偏置块。需要时可以直接建（一句话告知即可），用户删掉则不重建。项目索引记事实、价值偏置记判据，不混在一份手册里。

## 项目索引

用户的项目散在几台 Worker 的不同目录里，也可能只存在于某个远端仓库或一个域名上。项目索引一段一个项目，只记「它在哪里 + 它是什么」：不解释项目，只做路由——读到一段就该知道去哪个 Worker 的哪个目录，或 clone 哪个远端。

何时动它，只在「位置」出现或变化时：新建或克隆 → 加一段；搬到别的 Worker、换路径、换远端 → 改那段；归档、删除 → 删那段；干活时发现位置不对（`cd` 进去是空的、目录改名、远端 404）→ 以实际为准当场更正，并一句话告诉用户。不做定期巡检、不为「刷新索引」全盘扫描、不补核对日期——维护成本必须接近零。

三段式 `项目 / 位置 / 简介`：

```text
# 项目索引

> 一条一个项目，三段式：项目 / 位置 / 简介。位置写「Worker 标签:路径」或远端仓库地址；只做路由，不写状态与进度。

项目: Cybion
位置: MacMini:~/Projects/cybion · github.com/zccz14/cybion
简介: Cybion 控制器与 Web 前端的单仓；Rust 服务 + TypeScript 前端，产物随 tag 发布
```

- 项目：用户平时怎么叫它就怎么写，不要自造别名。
- 位置：`Worker 标签:路径`（标签与 `cybion_list_workers` 返回的 `label` 一致）、远端仓库地址、线上地址，用 ` · ` 分隔；同一项目在多台 Worker 都有 clone 时逐个写。
- 简介：它是什么、为谁存在，以及怎么进去（入口脚本、数据文件在哪、页面路由）——这些也算路由。仍不写状态、进度、TODO、密钥与账号。

建与改：先 `list_manuals`，用户本地已有同类手册（「项目索引」或「项目目录」）→ 就地复用并遵守它自己的字段，不建第二份、不按本页字段改写它；没有则第一次有东西可记时用 `write_manual` 在顶层建，一句话告知，名字建议「项目索引」。改的时候只动那一段；用户自己写的段是权威，要改先问。用户删掉的不要自动重建。

坑：只凭目录名猜简介（至少看 `README` 或 `git remote -v`，不确定写 `?`）；把索引写成知识库（架构细节、部署步骤、密钥、账号、内网地址、客户名单都不进）；位置写相对路径；把「远端仓库」当成「能干活的位置」（远端是 clone 的来源，动手前先确认本地 clone 在哪台 Worker）。

## 价值偏置

模型在训练时被刻意去偏见化了，但用户真正想要的是**他自己的偏置**：同样两个选项，他和别人选得不一样，而且他认为那是显然的。记忆只让你知道用户是谁；价值偏置才让你在冲突时替他做决定。这份手册由你替他维护：捕捉他在真实取舍上的选择，记录成可执行的判据，下次先用，用完给他推翻的机会。

什么算一条——只记「无法从事实推导出来」的选择，四种形态：两难取舍（快 vs 对、便宜 vs 稳、省事 vs 可控、隐私 vs 便利——他选了哪个、牺牲了哪个）；纠正（「不，别这样」——被否决的是一类做法，不是那次操作）；反直觉的容忍（明知有损仍然接受；能容忍的边界比偏好本身更有信息量）；计量单位（他用钱、时间还是复杂度衡量一件事，预算不够时先砍什么）。不算：一次性的临时要求、环境事实、能写进项目文档的技术约定。

怎么捕捉——三个时机：他做了一次取舍 → 记「选项 A / 选项 B / 他选了 / 代价」；他否决了你的方案 → 记被否决的做法类别；同一张力第二次出现且他选择一致 → 写成更一般的判据。张力出现但他没表态时，问一个问题、不是问卷，而且必须带代价（「A 今天能上线，但脏数据要下周清；B 多两天，上线即干净」），一次会话最多问一个；他不回答就按当前最省事的那条走，并说明你按什么走的。

四段式 `场景 / 张力 / 选择 / 依据`，`依据` 是列表、每条带日期与出处（原话优先），列表项在 `依据:` 之后空一行：

```text
# 价值偏置

> 一条一个场景，四段式：场景 / 张力 / 选择 / 依据。依据是列表，每条带日期与出处；块与块之间空一行。

场景: 故障修复
张力: 彻底修 vs 先恢复服务
选择: 先恢复服务——线上故障优先恢复可用性，根因修复可以排到之后
依据:

- 2026-02-11 · 终极机器磁盘检查
```

- 场景：粗粒度类别（故障修复 / 代码风格 / 沟通 / 花钱），不要用项目名，否则复用时匹配不上。
- 张力：两个都说得通、却只能要一个的东西。
- 选择：他实际选的那一边，后面直接跟可执行的判断句；写不出判断句说明还只是偏好，只留依据、别写成规则。
- 依据：`YYYY-MM-DD` + 出处（Thread 标题、关键词或原话）；只出现过一次的选择注明「仅一次，待二次确认」，不当通用规则用。

怎么用：同类张力再出现时先按已记录的块行动并点明（「按你之前的选择，我先…」），给他当场推翻的机会；两块打架按最近的那块并说明理由；被推翻的块直接删，不留「已过时」；规则频繁冲突说明粒度抓错了，往上合并一层。

止损：不写画像（「他喜欢简洁」这种空话一律不写）；不升级太快（只出现一次的留在依据里，等第二次一致）；不追问（已有块覆盖的场景不再确认）；不写敏感内容（薪资、健康、住址、账号、客户名单都不进手册，只写决策形状）；一份就够，顶层、名字建议「价值偏置」、约 60 行以内，超了按场景合并，不拆子手册。

## 用户手册格式

用户手册是给模型反复读、被机械增改的**上下文**，不是给人读的文章：格式不对，每次维护都会变成重写，每次重写都会漂移。本页是默认格式；用户本地有同名手册时以本地为准。

一条一个块，块间空一行；字段名以半角冒号结尾，顺序固定，由手册开头那一行 `>` 声明。硬规定：

1. 一条一个块，字段顺序固定，字段名以半角 `:` 结尾。
2. 不用表格、不用 `|` 分隔、不嵌套、不加小标题；块间空一行。
3. 列表字段（如 `依据:`）的列表项另起一段：`字段:` 之后空一行再写 `- `，否则 Markdown 不会渲染成列表。
4. 日期一律 `YYYY-MM-DD`。
5. 只写可判定的判据与事实，不写背景故事、不写画像。
6. 增改不重写：追加一个块，或就地改那一个块；重组整份手册（改字段、改分节、批量删）前先问用户。
7. 被推翻的块直接删，不留「已过时」——残留条目会继续被读进上下文。
8. 收敛：同类条目超过 3 个就合并成更一般的；整份约 60 行以内。

那一行 `>` 既是给人的口径，也是给你看的字段契约：改字段之前先改它；它和条目对不上时以 `>` 行为准，并顺手把条目改齐。

分工：Note 记这一轮的目标与 TODO，做完划掉；Manual 记跨轮次、跨压缩都要在的判据（用本页格式）；Archive 只追加、不复盘。建手册的时机：钩子真的触发了再建，不预建空手册；建的时候一句话告知用户（可改、可删）；用户删掉的不自动重建。

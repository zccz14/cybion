# 项目索引

用户的项目散在几台 Worker 的不同目录里，也可能只存在于某个远端仓库或一个域名上。**项目索引**是一份用户手册，一段一个项目，记「它在哪里 + 它是什么」。它不解释项目，只做路由：读到一段，你就知道该去哪个 Worker 的哪个目录，或者该 clone 哪个远端。

它和「价值偏置」是用户的两份常备手册：项目索引记**世界长什么样**，价值偏置记**用户怎么判断**。事实与判据，不混在一份手册里。

## 什么时候动它

只在「位置」出现或变化时：

- 新建、克隆了一个项目 → 加一段。
- 项目搬到别的 Worker、换了路径、换了远端 → 改那一段。
- 项目归档、删除 → 删那一段。
- 干活时发现位置不对（`cd` 进去是空的、目录改名了、远端 404）→ **以实际为准当场更正**，并一句话告诉用户「索引写的是 A，实际是 B，已更正」。

不做：定期巡检、为「刷新索引」全盘扫描 `~/Projects`、给每段补「最近核对日期」。索引的维护成本必须接近零，否则没人会维护它。

## 一段怎么写

三段式：`项目 / 位置 / 简介`。

```text
# 项目索引

> 一条一个项目，三段式：项目 / 位置 / 简介。位置写「Worker 标签:路径」或远端仓库地址；只做路由，不写状态与进度。

项目: Cybion
位置: MacMini:~/Projects/Cybion · github.com/zccz14/cybion
简介: Cybion 控制器与 Web 前端的单仓；Rust 服务 + TypeScript 前端，产物随 tag 发布
```

- **项目**：用户平时怎么叫它就怎么写，不要自造别名。
- **位置**：`Worker 标签:路径`（标签与 `cybion_list_workers` 返回的 `label` 一致，读到一段就能对上 `worker_id`）、远端仓库地址、线上地址，用 ` · ` 分隔；同一项目在多台 Worker 都有 clone 时逐个写。
- **简介**：它是什么、为谁存在，以及**怎么进去**（入口脚本、数据文件在哪、页面路由）——这些也算路由。仍然不写状态、进度、TODO、密钥与账号。

## 建与改

- 先 `list_manuals`：用户本地已有同名手册（「项目索引」或「项目目录」）→ **就地复用**，并遵守它自己的字段；不要建第二份，也不要按本页字段去改写它。
- 没有 → 第一次有东西可记时直接建（`write_manual`，顶层），一句话告知用户，名字建议 `项目索引`。
- 改的时候只动那一段；用户自己写的段是权威，要改先问。
- 用户删掉了这份手册 → 不要自动重建。

## 坑

- **只凭目录名猜简介** → 至少读一眼 `README` 或 `git remote -v`；不确定就写 `?`，下次遇到再补。
- **把索引写成知识库** → 架构细节、部署步骤、密钥、账号、内网地址、客户名单都不进这份手册。
- **位置写相对路径** → 必须 Worker 标签 + 路径或远端地址，否则下次不知道去哪台机器找。
- **把「远端仓库」当成「能干活的位置」** → 远端是 clone 的来源，不是执行面；动手前先确认本地 clone 在哪台 Worker 上。

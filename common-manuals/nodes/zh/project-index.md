# 项目索引

用户的项目散在几台 Worker 的不同目录里，也可能只存在于某个远端仓库。**项目索引**是一份用户手册，把「项目 → 它在哪里 + 它是什么」记成一行一条。它不解释项目，只做路由：读到一行，你就知道该去哪个 Worker 的哪个目录，或者该 clone 哪个远端。

它和「价值偏置」是用户的两份常备手册：项目索引记**世界长什么样**，价值偏置记**用户怎么判断**。事实与判据，不混在一份手册里。

## 什么时候动它

只在「位置」出现或变化时：

- 新建、克隆了一个项目 → 加一行。
- 项目搬到别的 Worker、换了路径、换了远端 → 改那一行。
- 项目归档、删除 → 删那一行。
- 干活时发现位置不对（`cd` 进去是空的、目录改名了、远端 404）→ **以实际为准当场更正**，并一句话告诉用户「索引写的是 A，实际是 B，已更正」。

不做：定期巡检、为「刷新索引」全盘扫描 `~/Projects`、给每行补「最近核对日期」。索引的维护成本必须接近零，否则没人会维护它。

## 一行怎么写

`名称 | 位置 | 简介`

```text
# 项目索引

> 一行一个项目：名称 | 位置 | 简介
> 位置写「Worker 标签:路径」或远程仓库地址；本地与远端都有时两个都写，用 · 分隔。

Cybion | MacMini:~/Projects/Cybion · git@github.com:zccz14/cybion.git | Cybion 控制器与 Web 前端（Rust + TypeScript 单仓）
示例项目 | Linux US:/srv/example | 一句话说明这个项目是做什么的
```

- **名称**：用户平时怎么叫它就怎么写，不要自造别名。
- **位置**：`Worker 标签:路径`（标签与 `cybion_list_workers` 返回的 `label` 一致，读到一行就能对上 `worker_id`），或远端仓库地址。两者都有时，先写能直接干活的本地路径；同一项目在多台 Worker 上都有 clone 时每个都写，用 `·` 分隔。
- **简介**：一句话讲清「这是什么、为谁存在」。**不写状态、进度、TODO、技术栈清单**——写了它就从路由变成项目文档，然后开始过期。

## 建与改

- `list_manuals` 里已有同类手册（名字类似「项目索引」或「项目目录」）→ **就地复用**，不要建第二份。
- 没有 → 第一次有东西可记时直接建（`write_manual`，顶层），并一句话告知用户：「我给你建了《项目索引》，以后新项目会自动补一行」。名字建议就叫 `项目索引`。
- 改的时候**只增改该改的那一行**，其他行原样保留；用户自己写的行是权威，要改先问。
- 用户删掉了这份手册 → 不要自动重建。
- 条目到约 60 行时，先合并「同一仓库的多个 clone」这类重复行，再考虑分节。

## 坑

- **只凭目录名猜简介** → 至少读一眼 `README` 或 `git remote -v`；猜错比留空更坏，不确定就写 `?`，下次遇到再补。
- **把索引写成知识库** → 架构、部署、密钥、账号、内网地址、客户名都不进这份手册，它会被模型反复读进上下文。
- **位置写相对路径** → 必须写 Worker 标签 + 路径或远端地址，否则下次不知道去哪台机器找。
- **把「远端仓库」当成「能干活的位置」** → 远端是 clone 的来源，不是执行面；动手前先确认本地 clone 在哪台 Worker 上。

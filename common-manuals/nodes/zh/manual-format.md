# 用户手册格式

用户手册是给模型反复读、被机械增改的**上下文**，不是给人读的文章。格式不对，每次维护都会变成重写，每次重写都会漂移。

本页是**默认格式**。如果用户的本地手册里有一份「用户手册格式」，以本地为准——它覆盖本页。

## 块格式

一条一个块，块间空一行；字段名以半角冒号结尾，顺序固定，由手册开头那一行 `>` 声明。

```text
# <手册名>

> 一条一个 <单位>，<段数>段式：字段一 / 字段二 / 字段三。其余口径写在这里。

字段一: ...
字段二: ...
字段三:
- 需要多行时用列表
- 每行一条
```

## 硬规定

1. 一条一个块，字段顺序固定，字段名以半角 `:` 结尾。
2. 不用表格、不用 `|` 分隔、不嵌套、不加小标题；块间空一行。
3. 日期一律 `YYYY-MM-DD`。
4. 只写可判定的判据与事实，不写背景故事、不写画像。
5. 增改不重写：追加一个块，或就地改那一个块；重组整份手册（改字段、改分节、批量删）前先问用户。
6. 被推翻的块直接删，不留「已过时」——残留条目会继续被读进上下文。
7. 收敛：同类条目超过 3 个就合并成更一般的；整份约 60 行以内。

## 那一行 `>`

它既是给人看的口径，也是给你看的：声明字段与顺序。改字段之前先改它；它和条目对不上时，以 `>` 行为准，并顺手把条目改齐。

## 分工

- **Note**：这一轮的目标与 TODO，做完划掉。
- **Manual**：跨轮次、跨压缩都要在的判据——用本页格式。
- **Archive**：只追加、不复盘的历史。

## 建手册的时机

- 钩子真的触发了（有第一个项目要记、有第一条偏置要记）再建，不预建空手册。
- 建的时候一句话告知用户，让他知道这份手册存在、可以改、可以删。
- 用户删掉的手册不要自动重建。

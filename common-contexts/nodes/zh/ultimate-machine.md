# Ultimate Machine（终极机器）

一台终极机器 = 一个 Worker + 一条 bash 检查命令 + 一个运行间隔。它按期运行：返回 0 就保持沉默；失败时，控制器把修复请求投递到它绑定的修复 Thread（标题形如「终极机器 · <名称>」）。

名字来自贝尔实验室的玩笑盒——那台唯一的功能就是把自己关掉的机器。这里的机器延续同一种幽默：平时什么都不做，只在检查失败时现身；命令回到 0 之后，再次安静下来。

## 关键语义

- **调度**：创建后立即执行第一次；之后每次运行在「上一次运行落定 + 间隔」时开始（慢命令会拉长实际周期），同一台机器同时最多一次运行。
- **失败**：exit ≠ 0（或命令被杀）→ 修复 Thread 收到一条用户消息：命令、exit、输出尾部、意图（若有）与成功判据「使该命令返回 0」。
- **离线**：运行时刻 Worker 离线或已不存在 → 跳过本次，通过 Linkit 提醒一次，长中断期间保持安静；恢复后自动继续（每个离线事件只提醒一次）。
- **失联**：一次运行 15 分钟仍未落定（设备中途死亡等）→ 判定失联，提醒一次，下个间隔重试。
- **丢消息**：修复 Thread 正在运行时，新的失败消息会被丢弃（不是排队）——它会在下一次运行落定后重新决定是否投递；因此静默既不代表健康，也不代表机器坏了。
- **生命周期**：删除绑定的修复 Thread 或它使用的 Worker，会随之删除机器；改绑 Worker 会重启离线提醒事件（视作新的一轮）。

## 何时开一台

适合交给终极机器的，是**长期存在、可以自动判定「健康」**的条件：

- 资源水位：根分区 / 数据盘使用率、inode 剩余、内存与交换占用。
- 「到期」类：TLS 证书剩余天数、备份窗口、磁盘配额。
- 服务存活：本地端口可连、systemd 单元处于 active、关键进程存在。
- 数据新鲜度：同步任务留下的「最后一次成功」时间戳在允许窗口内。
- 一致性：关键文件存在且非空、校验和与预期一致。

不适合的场景：

- 一次性任务，或需要人判断的事项。
- 高频轮询——间隔下限 10 秒，多数检查分钟到小时级就够。
- 需要「修复动作」本身：机器只负责发现，修复发生在绑定 Thread 里。
- 输出可能包含密钥、令牌或隐私数据：失败输出尾部会进入 Thread 历史。

创建入口：用户可在「终极机器」页面手动创建（选 Worker、填命令与间隔）；当用户要求时，你也可以用 `cybion_set_ultimate_machine` 直接创建（用法见下文「管理工具」）。不变的正道：先在目标 Worker 上用 bash 干跑验证命令。

## 怎么写检查命令

准则：

- **退出码即语义**：0 = 健康且沉默；任何非 0 = 失败，stderr/stdout 的尾部（约 1500 字符）会被送进修复 Thread。让失败自己说话。
- **只读、幂等**：反复运行不改动状态、不产生副作用文件。
- **便宜**：单次运行上限 300 秒（由 Worker 端计时，超时被杀同样算失败）；毫秒级读完最好。
- **不依赖登录环境**：按非交互 shell 写（显式路径、不依赖 shell 配置）；注意 Worker 系统差异（macOS 与 GNU 工具行为不同）。
- **失败可行动**：输出里带上期望值与现状，修复者不用二次侦查。

示例：

- 根分区使用率 < 90%：
  `test $(df -Pk / | awk 'NR==2 {print $5}' | tr -d %) -lt 90`
- 证书 7 天内不过期（未临近过期时 exit 0）：
  `openssl x509 -checkend 604800 -noout -in /etc/ssl/certs/server.pem`
- 24 小时内有新备份文件：
  `find /backups -maxdepth 1 -type f -mmin -1440 | grep -q .`

上手前先干跑：用 bash 工具在目标 Worker 上运行同一命令——确认健康态返回 0，并人为制造失败，检查输出是否可读。

## 管理工具（tool 套件）

管理终极机器有三件工具：`cybion_list_ultimate_machines`、`cybion_get_ultimate_machine`、`cybion_set_ultimate_machine`。字段级语义以工具描述为准；这里是使用套路。

### 何时用哪件

- **看全貌、找 id**：`cybion_list_ultimate_machines`——每台机器的定义 + 最近一次落定结果（`enabled`、`last_run_at`、`last_exit`、绑定的修复 Thread）。
- **看一台的细节**：`cybion_get_ultimate_machine`——`last_exit`：0 = 正常；其他数字 = 退出码（被杀且无退出码记为 -1）；null = 尚无落定结果（或该次执行未完成/已失联）。
- **新建或修改**：`cybion_set_ultimate_machine`。

### 新建（省略 machine_id）

必填 `name`、`worker_id`、`command`、`interval_seconds`（10–2592000 秒）；可选 `intent`。

- 只能绑定**你拥有的** Worker（共享 Worker 不能跑机器）；拿不准先 `cybion_list_workers`。
- 创建后立即执行第一次，并自动创建修复 Thread「终极机器 · <名称>」。
- 创建前先干跑：用 bash 在目标 Worker 上运行同一命令，确认健康态返回 0、失败输出可读。
- 典型请求「给 MacMini 加一个磁盘检查」：list_workers → bash 干跑 → set 创建 → 一句话向用户确认，别粘贴全文。

### 修改（带 machine_id，局部更新）

- 只提供要改的字段，其余保持不动。
- `intent` 传空串清空意图；省略则保留。
- `enabled: false` 暂停、`true` 恢复（新机器默认启用；`enabled` 仅在更新时可传）。
- 改 `worker_id` 会把机器搬过去，并重启「离线提醒」事件。
- 改名会同步修复 Thread 标题（手动改过标题的除外）。
- 三件套没有删除：要停就暂停；彻底移除由用户删除绑定的修复 Thread 或它使用的 Worker。

机器是用户的资产：只在用户明确要求或修复需要时创建/修改；批量动作先说计划。

## 失败之后

修复 Thread 收到的消息形如：

```text
【终极机器·磁盘检查】在 Worker「MacMini」上执行失败：exit=1。

意图：
确保根分区低于 90%

命令：
test $(df -Pk / | awk 'NR==2 {print $5}' | tr -d %) -lt 90

输出尾部：
...
请修复，使该命令返回 0；修好后无需回复，下次运行会自动验证。
```

工作流：

1. **读定义与证据**：先用 `cybion_get_ultimate_machine` 看定义与最近结果；再读消息里的命令、exit、输出尾部；「意图」说明这台机器在保护什么。
2. **判断问题在哪**：
   - 环境问题（磁盘真的满了、证书真过期了、服务挂了）→ 用 bash 在对应 Worker 上直接修。
   - 检查本身写错了（路径变了、命令与系统不兼容）→ 先用 bash 验证修正后的命令，再用 `cybion_set_ultimate_machine` 更新机器定义；工具不可用时，请用户在「终极机器」页面修改。
3. **验证**：手动运行修正后的命令，确认返回 0。
4. **别为了变绿而弱化检查**：悄悄放宽 exit 0 的语义等于失去这台机器。
5. **无需回复**：下次运行会自动验证；此后持续静默即修复成功。

## 边界与坑

- **暂停 ≠ 删除**：`enabled=false`（或 `cybion_set_ultimate_machine` 传 `enabled=false`）只是暂停；彻底移除请删除绑定的修复 Thread 或它使用的 Worker。
- **敏感信息**：失败输出会进入 Thread 历史——不要 echo 密钥/令牌；确需检查令牌有效性时，只输出布尔判断。
- **环境差异**：命令由 Worker 的执行环境运行；不要假设 PATH、locale、时区一致。

# 何时开一台

适合交给终极机器的，是**长期存在、可以自动判定「健康」**的条件：

- 资源水位：根分区 / 数据盘使用率、inode 剩余、内存与交换占用。
- 「到期」类：TLS 证书剩余天数、备份窗口、磁盘配额。
- 服务存活：本地端口可连、systemd 单元处于 active、关键进程存在。
- 数据新鲜度：同步任务留下的「最后一次成功」时间戳在允许窗口内。
- 一致性：关键文件存在且非空、校验和与预期一致。

不适合的场景：

- 一次性任务，或需要人判断的事项。
- 高频轮询——间隔下限 10 秒，多数检查分钟到小时级就够。
- 需要「修复动作」本身：机器只负责发现，修复发生在绑定 Thread 里。
- 输出可能包含密钥、令牌或隐私数据：失败输出尾部会进入 Thread 历史。

创建入口：目前由用户在「终极机器」页面创建（选 Worker、填命令与间隔）。AI 帮忙的正道：先在目标 Worker 上用 bash 干跑验证命令，再给用户创建建议；如当前会话提供机器管理工具，也可直接创建或更新。

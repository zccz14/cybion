# 失败之后

修复 Thread 收到的消息形如：

```text
【终极机器·磁盘检查】在 Worker「MacMini」上执行失败：exit=1。

意图：
确保根分区低于 90%

命令：
test $(df -Pk / | awk 'NR==2 {print $5}' | tr -d %) -lt 90

输出尾部：
...
请修复，使该命令返回 0；修好后无需回复，下次运行会自动验证。
```

工作流：

1. **读证据**：命令、exit、输出尾部；「意图」说明这台机器在保护什么。
2. **判断问题在哪**：
   - 环境问题（磁盘真的满了、证书真过期了、服务挂了）→ 用 bash 在对应 Worker 上直接修。
   - 检查本身写错了（路径变了、命令与系统不兼容）→ 先用 bash 验证修正后的命令，再更新机器定义（如当前会话提供机器管理工具，直接更新；否则请用户在「终极机器」页面修改）。
3. **验证**：手动运行修正后的命令，确认返回 0。
4. **别为了变绿而弱化检查**：悄悄放宽 exit 0 的语义等于失去这台机器。
5. **无需回复**：下次运行会自动验证；此后持续静默即修复成功。

补充：若失败消息因修复 Thread 正忙而被丢弃，不必懊恼——机器会在下一次运行落定后重新决定是否投递。
